@agentcash/router

Payments, identity, and discovery
for agent-facing APIs.

One fluent builder. x402 and MPP payments, SIWX wallet identity, OpenAPI, and /llms.txt — all derived from your route definitions.

pnpm add @agentcash/router zod 
// server/router.ts
import { createRouterFromEnv } from '@agentcash/router';

export const router = createRouterFromEnv({
  title: 'My API',
  description: 'Pay-per-call API.',
  guidance: 'POST /search with { q: string }.',
});

// server/routes.ts
import { router } from './router';

router.route('search')
  .paid('0.01')
  .handler(async ({ body }) => search(body));

router.route('health')
  .unprotected()
  .handler(async () => ({ status: 'ok' }));

That's a working paid API. Everything below is additive.

01

Host it

The router is one fetch handler. Every registered route plus the discovery surfaces (/.well-known/x402, /openapi.json, /llms.txt) is served through it.

// app/api/[[...route]]/route.ts
import '@/server/routes'; // side-effect: registers all routes
import { router } from '@/server/router';
import { nextHandlers } from '@agentcash/router/next';

export const { GET, POST, PUT, PATCH, DELETE } = nextHandlers(router);

One file serves the whole API. Routes are registered before any request is handled — no barrel files, no module-load-order surprises.

The catch-all covers /api/*. To serve root-level aliases (/.well-known/x402, /llms.txt), add dedicated route files or a middleware rewrite:

// app/.well-known/x402/route.ts
import '@/server/routes';
import { router } from '@/server/router';
export const GET = router.wellKnown();

// — or — middleware.ts (rewrite into the catch-all)
export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;
  if (pathname === '/.well-known/x402' || pathname === '/llms.txt') {
    return NextResponse.rewrite(new URL(`/api${pathname}`, request.url));
  }
}
// app/api/search/route.ts
import { router } from '@/server/router';
import { searchSchema } from './schemas';

export const POST = router.route('search')
  .paid('0.01')
  .body(searchSchema)
  .handler(async ({ body }) => search(body));

.handler() returns a standard (request: Request) => Promise<Response> — Next.js accepts it directly. Because Next.js lazy-loads route modules, keep a barrel import in your discovery route files so all routes appear in the spec.

import { Hono } from 'hono';
import { serve } from '@hono/node-server';
import { createRouterFromEnv } from '@agentcash/router';
import { z } from 'zod';
import './routes'; // registers all routes
import { router } from './router';

const app = new Hono();
app.route('/', router.hono()); // or: serve({ fetch: router.fetch, port: 3000 })

serve({ fetch: app.fetch, port: 3000 });

router.fetch(request) is the raw entry point for any fetch runtime — Bun, Deno, Cloudflare Workers.

Path parameters

router.route('jobs/{jobId}')
  .siwx()
  .method('GET')
  .handler(async ({ params, wallet }) => getJob(params.jobId, wallet));

Use {param} segments — they're extracted into ctx.params in every hosting mode. The route mount prefix defaults to api; override with RouterConfig.basePath.

02

Primitives

Each route chains exactly one auth/pricing mode. The builder throws at registration if you combine incompatible modes — that constraint is the documentation.

.paid() — fixed, args-derived, or tiered

Static. Fixed price per request, settled via x402 or MPP.

router.route('search')
  .paid('0.01')
  .handler(async ({ body }) => search(body));

Args-derived. Compute the price from the parsed body before issuing the 402 challenge. maxPrice is required — it caps the computed amount and acts as a fallback on non-HttpError exceptions.

router.route('generate')
  .paid((body) => `${body.frames * 0.01}`, { maxPrice: '1.00' })
  .body(z.object({ frames: z.number() }))
  .handler(async ({ body }) => render(body));

Tiered. Pick a tier from a field in the parsed body.

router.route('upload')
  .paid({
    field: 'tier',
    tiers: {
      '10mb': { price: '0.02', label: '10 MB' },
      '100mb': { price: '0.20', label: '100 MB' },
    },
  })
  .body(uploadSchema)
  .handler(async ({ body }) => store(body));

Per-network payee. Route payouts to different addresses per chain:

.paid('0.01', {
  payTo: (request, body, network) =>
    network?.startsWith('solana:') ? SOLANA_TREASURY : EVM_TREASURY,
})

.upTo() — handler-computed, x402 only

The handler calls charge(amount) one or more times; the request settles once for the accumulated total, capped at maxPrice. Requires createRouterFromEnv (auto-adds the upto accept on Base) or a manual { scheme: 'upto', network, asset } entry in x402.accepts.

router.route('fortune/premium')
  .upTo('0.005')
  .body(PremiumSchema)
  .handler(async ({ body, charge }) => {
    const amount = computeCost(body);
    await charge(amount);
    return { result: await process(body) };
  });

.metered() — per-tick, MPP only

Per-tick billing over an MPP payment channel. Requires MPP_OPERATOR_KEY (enables session mode automatically via createRouterFromEnv).

Request-mode. Bills exactly tickCost per request:

router.route('fortune/llm')
  .metered({ tickCost: '0.001', maxPrice: '0.01', unitType: 'request' })
  .body(LlmSchema)
  .handler(async ({ body }) => generate(body));

Streaming. Each charge() call bills one tick. Streaming is MPP-only — .stream() on any other pricing mode throws at registration.

router.route('fortune/stream')
  .metered({ tickCost: '0.0001', maxPrice: '0.05', unitType: 'token' })
  .body(StreamSchema)
  .stream(async function* ({ body, charge }) {
    for await (const token of streamLLM(body.prompt)) {
      await charge();
      yield token;
    }
  });

.siwx() — wallet identity, no payment

Clients prove control of a wallet via a signed challenge. The verified wallet address is available as ctx.wallet in the handler.

router.route('fortune/profile')
  .siwx()
  .method('GET')
  .handler(async ({ wallet }) => getProfile(wallet));

.apiKey() — API key auth

Reads X-API-Key or Authorization: Bearer <key>. The resolver returns the account record, or null for 401. Composes with .paid() — key is checked first, payment second.

// Key only
router.route('admin/users')
  .apiKey(async (key) => db.admin.findByKey(key))
  .handler(async ({ account }) => db.user.list(account.orgId));

// Key AND payment
router.route('gated')
  .apiKey(resolver).paid('0.01')
  .handler(fn);

.unprotected() — public routes

No auth, no payment. ctx.wallet, ctx.payment, and ctx.account are null.

router.route('health')
  .unprotected()
  .handler(async () => ({ status: 'ok' }));

Schemas & typed context

Chain .body(), .query(), and .output() with Zod schemas. The builder propagates the types so ctx.body, ctx.query, and the result in .settlement() / .nextStep() are all fully typed. .query() also switches the route to GET automatically.

const SearchSchema = z.object({ q: z.string(), limit: z.number().default(10) });
const ResultSchema = z.object({ hits: z.array(z.string()) });

router.route('search')
  .paid('0.01')
  .body(SearchSchema)
  .output(ResultSchema)
  .handler(async ({ body }) => {
    // body: { q: string, limit: number }
    return { hits: await db.search(body.q, body.limit) };
  });

Attach discovery examples with .inputExample() and .outputExample() — validated against the schema at registration:

.body(SearchSchema)
  .inputExample({ q: 'cats', limit: 5 })
  .outputExample({ hits: ['cats are great'] })

Pre-payment validation. .validate(fn) runs after body parse but before the 402 challenge. Throw Object.assign(new Error('msg'), { status: 409 }) to reject with a custom status:

router.route('domain/register')
  .paid(calculatePrice, { maxPrice: '10.00' })
  .body(RegisterSchema)
  .validate(async (body) => {
    if (await isDomainTaken(body.domain)) {
      throw Object.assign(new Error('Domain taken'), { status: 409 });
    }
  })
  .handler(async ({ body, wallet }) => registerDomain(body.domain, wallet));

Pipeline order: body parse → validate → 402 challenge → payment verify → handler → settle

.description() vs .docs()

Two channels, two jobs. .description() is the one-sentence summary — it feeds the 402 payment challenge (capped at 400 chars on paid x402 routes by the facilitator) and the discovery one-liners. .docs() is unbounded long-form documentation for agents who inspect this specific route: model quirks, response interpretation, usage judgment. It's emitted only as the OpenAPI operation description, fetched on demand — never bloating the challenge or the global guidance.

router.route('image-to-3d')
  .paid('0.50')
  .description('Convert a 2D image into a textured 3D model.')
  .docs('image_style_url performs color/texture style transfer only — it does NOT ' +
        'transfer facial features or likeness. For character likeness, invest in ' +
        'the quality of the input image instead.')
  .body(schema)
  .handler(convert);

HttpError

Throw from handlers, pricing functions, or validators to return a specific HTTP status. Two forms — both work identically:

import { HttpError } from '@agentcash/router';

// Named class
throw new HttpError('Fortune too long (max 100 chars)', 400);

// Plain error with .status — works anywhere in the pipeline
throw Object.assign(new Error('Domain taken'), { status: 409 });
03

Compose

.paid().siwx() — pay once, replay free

The first request settles normally; the wallet is recorded in the entitlement store. Subsequent requests with a valid SIWX signature skip payment entirely. On .upTo() routes, charge() becomes a no-op on replay.

router.route('inbox')
  .paid('0.01').siwx()
  .handler(async ({ wallet }) => getInbox(wallet));

router.route('fortune/membership')
  .upTo('0.005').siwx()
  .handler(async ({ wallet, charge }) => {
    await charge('0.002'); // no-op on SIWX replay
    return { reading: getRandom(readings), wallet };
  });
Gotcha: serverless / multi-instance deployments must provide a real kvStore (Upstash / Vercel KV). Without one, the entitlement is kept in a per-process Map — a wallet that paid on instance A is treated as unpaid on instance B.

.nextStep() — structured chaining

Multi-step APIs usually rely on prose to tell agents what to call next. .nextStep() makes the chain a deterministic, structured property of the route, declared where the route is defined. On a 2xx plain-JSON response, the router appends a next array — fully resolved URL, method, auth mode, and price, all derived from the target route's own definition.

router.route('videos/generate')
  .paid('0.40')
  .body(generateSchema)
  .output(z.object({ jobId: z.string() }))
  .nextStep({
    route: 'jobs/{jobId}',
    args: (result) => ({ jobId: result.jobId }), // typed from .output()
    note: 'Poll every ~5s until status is "complete".',
  })
  .handler(async ({ body }) => startJob(body));

The response body gains a reserved next array:

{
  "jobId": "abc123",
  "next": [{
    "method": "GET",
    "url": "https://api.example.com/api/jobs/abc123",
    "auth": "siwx",
    "note": "Poll every ~5s until status is \"complete\"."
  }]
}

For a paid target, price is included so the agent knows the cost before committing:

{
  "next": [{
    "method": "POST",
    "url": "https://api.example.com/api/download",
    "auth": "paid",
    "price": "0.05"
  }]
}

// dynamic/tiered pricing expresses as a range
{ "price": { "min": "0.01", "max": "0.25" } }

args() fills {param} slots in the target path. Leftover keys become query params on GET targets, or a suggested body object on POST targets. It also receives the original request as a second argument — args: (result, { body, query, params }) => ... — so a chain can reuse caller-sent values the result doesn't echo (a status route polling itself with the caller's token). A handler-supplied next key always wins — the router never overwrites it. Errors in when()/args() are reported via onAlert and skipped; they never break the response.

Set a machine-readable polling cadence with retryAfterSeconds — it's emitted verbatim on the entry, so clients can sleep deterministically instead of parsing prose:

.nextStep({ route: 'jobs/{jobId}', args: (r) => ({ jobId: r.jobId }), retryAfterSeconds: 5 })

External steps — when the next call isn't your route

Some flows hop through a third-party request: buy an upload slot, then PUT the bytes to a presigned S3 URL from the result. Declare it with external — the resolver derives the request from the actual result:

router.route('upload')
  .paid('0.01')
  .output(uploadSlotSchema)
  .nextStep({
    external: (r) => ({ method: 'PUT', url: r.uploadUrl, headers: { 'content-type': r.contentType } }),
    note: 'Upload the raw file bytes, then use publicUrl.',
  })
  .handler(buySlot);

External entries are marked "external": true and carry no auth/price (unknowable for third-party hosts). Returning null skips the entry. Exactly one of route/external per step.

when() — conditional branching

A status route can chain to different successors depending on its own result. Call .nextStep() multiple times; each entry is independently filtered by its when() predicate.

router.route('jobs/{jobId}')
  .siwx().method('GET')
  .output(z.object({ jobId: z.string(), status: z.string() }))
  .nextStep({
    route: 'jobs/{jobId}/download',
    args: (r) => ({ jobId: r.jobId }),
    when: (r) => r.status === 'complete',
    note: 'Download is ready.',
  })
  .nextStep({
    route: 'jobs/{jobId}',
    args: (r) => ({ jobId: r.jobId }),
    when: (r) => r.status === 'pending',
    note: 'Still processing — poll again in ~5s.',
  })
  .handler(async ({ params }) => getJobStatus(params.jobId));

When all when() predicates return false, the next key is omitted entirely from the response.

Validate that all declared targets are registered (catches missing barrel imports at startup):

router.registry.validate(); // throws if any nextStep target is not registered

.settlement() — around on-chain settlement

Run app logic at precise points in the settlement lifecycle. With .output() declared, ctx.result is fully typed.

router.route('drafts/{draftId}/commit')
  .paid(quotePrice, { maxPrice: '50.00' })
  .body(CommitBody)
  .output(DraftResponse)
  .settlement({
    beforeSettle: async (ctx) => reserveInventory(ctx.result.draftId), // typed!
    afterSettle:  async (ctx) => recordLedgerRow(ctx),
    onSettlementError: async (ctx) => queueRefundReview(ctx),
  })
  .handler(commitDraft);
04

Discovery

Three discovery surfaces are generated automatically from the route registry. You write zero discovery code.

SurfacePathWhat's in it
/.well-known/x402 Auto-served via catch-all or router.wellKnown() Resource list, accepted protocols, instructions
/openapi.json Auto-served via catch-all or router.openapi() OpenAPI 3.1 spec — paths, schemas, payment info; output schemas of chained routes gain the optional next key
/llms.txt Auto-served via catch-all or router.llmsTxt() Plain-text guidance + auto-generated ## Workflows section

llms.txt sample output

When chains are declared, the router appends a ## Workflows section — the prose you used to hand-write, derived from the route graph. The same composed text rides into OpenAPI's info.x-guidance, so discovery clients that read guidance from the spec get the map too. Isomorphic chains (same steps, different root — think 100 generated routes that all poll the same status endpoint) dedupe into one representative line annotated (and N similar routes):

POST /api/search with { q: string }. Returns top 10 results.

## Workflows

Workflow 1:
1. POST /api/videos/generate ($0.40) — Start the run
2. POST /api/jobs/{jobId} (siwx, free) — Poll until status is "complete"
3. GET /api/jobs/{jobId}/download ($0.05) — Download once complete

This summary is the chain's only static trace — by design. A chain is dynamic three ways (URLs resolve from actual results, branches are when()-filtered, prices are current), so resolved edges live exclusively in the runtime next array where they can't go stale. Cycles are capped gracefully — the router never hangs on circular references.

05

Configure

createRouterFromEnv reads process.env, validates everything at startup, and throws a single RouterConfigError listing every problem. Use createRouter when you need custom networks, multiple payees, or any setting env doesn't expose.

import { createRouterFromEnv } from '@agentcash/router';

export const router = createRouterFromEnv({
  title: 'My API',
  description: 'Pay-per-call search.',
  guidance: 'POST /search with { q: string }. Returns top 10 results.',
});
import { createRouter, BASE_MAINNET_NETWORK } from '@agentcash/router';

export const router = createRouter({
  baseUrl: 'https://api.example.com',
  payeeAddress: '0x…',
  network: BASE_MAINNET_NETWORK,
  protocols: ['x402'],
  x402: { accepts: [/* … */] },
  discovery: {
    title: 'My API',
    version: '1.0.0',
    description: 'Pay-per-call search.',
    guidance: 'POST /search with { q: string }.',
  },
});

MPP_CURRENCY when MPP needed Tempo currency address. Use TEMPO_USDC_ADDRESS for Tempo USDC.

06

Observe

All observability is pluggable via RouterPlugin. Hooks are optional and fire-and-forget — they never delay the response.

import { createRouterFromEnv, type RouterPlugin } from '@agentcash/router';

const myPlugin: RouterPlugin = {
  onRequest(meta) {},
  onPaymentVerified(ctx, payment) {},
  onPaymentSettled(ctx, settlement) {},
  onResponse(ctx, response) {},
  onError(ctx, error) {},
  onAlert(ctx, alert) {},
};

export const router = createRouterFromEnv({
  title: 'My API',
  description: '…',
  guidance: '…',
  plugin: myPlugin,
});

Debugging with onAlert

Internal warnings — failed payment verification, simulation failures, misconfiguration — are routed through onAlert. With no plugin registered, they're silently dropped. Wire it up to see why a request failed:

const loggingPlugin: RouterPlugin = {
  onAlert(_ctx, alert) {
    (alert.level === 'error' ? console.error : console.warn)(
      `[router:${alert.route}] ${alert.message}`,
      alert.meta ?? '',
    );
  },
  onError(_ctx, error) {
    console.error(
      `[router] ${error.status} ${error.message} (settled=${error.settled})`,
    );
  },
};
